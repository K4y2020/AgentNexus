## cine-script

### 跨 skill 交接与适用范围

跨 skill 管线以 [production-handoff.md](../film-analysis/references/production-handoff.md) 为权威；本 skill 仍可独立使用，独立产物不自动代表全管线就绪。
先明确模式：`analysis` 只记录观察，`faithful` 忠实重建，`adaptation` 按已确认方案改编，`original` 原创。复用用户已给出的答案，只补缺失或冲突项；改编幅度不得默认“抽核”。来源观察保持不可变，与虚构改编分开保存；改编方案先于新分镜，按叙事功能映射来源，不逐切照搬。
合同哈希与上游版本 pins 存在 sidecar，不改 outline/cast/art/script/storyboard 五份原生 schema。共享检查命令为 `python <film-analysis>/pipeline/handoff.py <production.json>`；只检查结构交接就绪，不替代原生 validator、视觉 QA 或运行时来源门，更不是 production PASS。共享文件/检查器不可用时明确交接检查受阻，不伪造通过。
本文及下级参考中的风格、钩子、爽点门限用于短剧；非短剧保留原作节奏，不为过门改成爽剧。仅使用现有参数；不支持的风格/提供商门如实报告不兼容，不编造 CLI 开关或绕过校验。
Cine 负责制作，V3 保留画布和 workers。先 `seedance_read_canvas` 再 `seedance_edit_canvas`；更新/删除带读到的 `expected_revision`，冲突先重读，删除另需 `confirm: true`。生成须已有明确范围授权才可 `submit_generation` 并置 `generation_allowed=true`，重试也须在授权范围内，不承诺免费。
V3 Agent 仅定位为 QA；现有 `seedance_agent_message` 没有代码级只读隔离。只读 QA 强制隔离落实前，在本地或只读快照上检查，禁止用泛用 Agent 消息冒充安全 QA，也不通过它委托制作。禁止 codex `$imagegen` 及其 fallback。
渲染图像字段只接受真实本地图像路径，不能填远程 asset ID。画布引用反过来需要已上传的真实资产及返回 ID，不能拿本地路径冒充远程引用；上传/引用能力不可用就阻塞。路径、旧文件、任务状态都不是图像证据；核对本次来源并实际看图后才可验收。不可用图像保持缺失，阶段校验通过不等于制作通过。
`analysis` 在来源分析结束，不进入 novel 制作阶段。跨 skill 的 `source-material.json`、`shot-mapping.json` 按共享合同组织，原始观察与解读分离；未知身份、对白和动作保持未知。使用实际文件哈希，不能只刷新 pins 来消除过期错误，须先复核受影响的下游产物。


给 AI 短剧写**剧本**。**前提刻在骨子里：剧本管戏，分镜管拍**——「爽不爽」和「怎么拍」是两种迭代节奏，台词要反复推翻重写，绑上镜头分解每改一句都得重排镜头。所以这层只有集、场次、节拍流，没有镜号；镜头、首帧提示词、生成批次都是下一层分镜 skill 的活。

但有一条底线：**台词必须是结构化数据，不能写成散文**。每句台词是独立条目（说话人 + 台词 + 语气），动作是独立节拍——这是全部确定性检查的地基：

| 交付 | 解决什么 |
| --- | --- |
| 逐集时长预算 | 一集三分钟就是三分钟：台词按语速折算、动作按节拍估时，写超写欠当场拦下，不流到生成环节才发现 |
| 节拍流（动作 ⇄ 台词） | 台词直接对接 TTS 逐句生成；动作节拍就是画面要发生的事。混成散文两头都喂不进管线 |
| 每场至少一个动作节拍 | 纯对白的场是广播剧——AI 生成时没有画面可写 |
| 开场钩子 + 结尾悬念 | 短剧的生死线，每集都要落在纸面；**钩子不是标签是第一拍**——`hookBeat` 认领具象位置，必须落在全集前 3 拍内（冷开场） |
| 爽点认领 | 大纲说这一集有大爆点，剧本必须有戏认领它——防止改着改着把爆点改丢 |
| 上游对账 | 场景/光照/道具对 art.json、角色对 outline.json，写了美术没登记的光照状态当场报 |

`{baseDir}` = 本文件所在目录。脚本 `{baseDir}/scripts/cine-script.mjs`，零依赖，`node` 直接跑。

**边界（不做的事）**：不分镜头、无镜号、不写画面生成提示词、不出图、不配乐——分镜层的活一件不碰。不改大纲结构（砍线合人是 `cine-outline` 的活）；不做角色和场景设定（`cine-characters` / `cine-art` 的活）。

### Step 0 — 定输入与范围

**outline.json 是长篇改编/分集剧本的直接上游**（分集梗概、爽点落点、单集时长都在里面）。单场短片已有明确人物、情节和目标时长时直接写戏，不强制补跑大纲；缺少影响创作的关键信息才提问。仍用原生骨架，缺失上游的对账门如实标为跳过。

**一次写几集**：默认一批 ≤ 3 集。剧本是全管线改得最凶的一层，小批量出、快拍板、再往下写。用户明确要全剧也分批产出，每批过一次校验。

顺手带上（都可选，给了才对账/显示名字）：

- `--outline`：角色引用对账 + 爽点认领检查 + 报告里 C01 显示成人名
- `--art`：场景/光照状态/道具对账 + 报告里 S01 显示成场景名
- `--cast`：角色服装／伤势状态对账；新 seed 的每场 `characterStates` 必须覆盖全部出场角色

写场次前先列“角色 × 场景”状态矩阵。默认造型写 `default`，换装、睡衣、病号服、受伤、湿身等可见变化写稳定状态 ID（如 `home_morning`、`hospital_injured`）。状态变化是资产事实，不得只埋在动作 prose 里；非默认状态必须先在 `cast.json.states` 建独立 descriptor 和设定图提示词。

### Step 1 — seed 骨架

写对白前，先在工作笔记中用几句话明确每场的目标、阻力、角色换招、转折触发和结尾变化。
用“因为—所以—但是”检查因果：角色依据什么可感知的信息行动？
关键转折是否来自先前的选择或新信息？不要用后加广播或旁白替代戏中缺失的因果。
不新增原生 JSON 必填字段，不为写检查表另造脚本。

创作复看与结构校验分开：删除一段对白后，人物关系或事件是否仍有变化？
主要转折给一个具体反应或选择，不把“惊恐、呆滞、震惊”当成完整表演。
保留已确认的类型与笑点目标；修逻辑不默认改成温情、写实或沉重风格。
需要改世界观、结局或上游角色设定时，提出候选与代价，不悄悄覆盖已确认稿。
自评引用具体节拍及问题，不以字段全绿、虚构评分或百分比证明“好看”。
修订后逐项回看自己诊断的问题，指出新稿哪一个事件真正解决它；未解决就明说。
核对角色当时已知的信息与行动顺序，不能靠人物无依据地忘记信息或改变能力推动剧情。
区分阻碍理解的矛盾与类型片允许的省略：已建立的荒诞、奇幻约定不必逐条解释，
不要为补背景规则塞入说明对白、消除笑点或把所有故事改成写实剧。风格随剧本需要变化。

```bash
node {baseDir}/scripts/cine-script.mjs seed <outline.json> --eps 1-3 > <workdir>/script.json
```

确定性搬运：目标秒数（单集分钟 × 60）、钩子、悬念、该集爽点认领、候选场景与人物（进 `seedNote`）。**这些事实不要让模型重新想一遍。** scenes 留空，那才是写戏的活。

### Step 2 — 逐集写戏

<!-- cine-core:start -->
以下是必读创作流程，已随入口完整返回，无需再次读取 pass 参考文件。
输入为当前大纲、角色与场景设定、前集结尾和本集 seed；输出仍为原生 `scenes/flow`。
不改原生 schema。以下创作审查不代替 validator，也不是机器可证明的观赏性评分。

#### 先交付一份能直接读的剧本

首稿首先服务观众、演员和下游制作，不服务创作者的自我解释。只把可见动作、可听声音和角色真正说出口的话写进 `flow`；“他主动撒谎”“她允许记忆靠近”“两人仍有选择”“这个空位就是答复”这类作者判断留在工作笔记，不能冒充动作或 `delivery` 渲染到剧本。
动作条目必须能由演员、道具或环境照字面执行。无法被看见或听见的心理结论，改成能改变局面的行为，或从正文删除。`delivery` 只写演员能执行的声音和身体提示，例如压低声音、说到一半停住、手仍按着门把；不写潜台词释义、主题分析或观众应当如何理解。

先做一次“陌生观众读本”：不看大纲、工作笔记和创作说明，只读渲染后的正文，仍应看懂谁要什么、失败会失去什么、何时获得关键信息、做了哪个有代价的选择、结尾改变了什么。缺失的信息用最短的动作或必要对白补足。随后再删掉重复画面信息、紧跟可见动作又复述其含义的台词、替观众下结论的台词，以及换个角色也能说的主题金句。历史或世界观背景只保留理解当前冲突所必需的部分，并让它参与试探、威胁或交换，不写成给观众听的说明课。可读不等于解释殆尽：事实和因果要清楚，意义允许观众自己完成。

#### 先拆人物，再写对白

多角色或改编剧本不能只拿情节梗概直接写台词。已有 `cast.json` 时必须读取实际出场角色的 `oneLiner` 与 `persona`，不能只拿姓名和外貌；没有角色卡的短场，先从原素材或已确认 brief 为每个说话角色写一张临时“场内说话卡”，放在工作笔记，不新增交付 schema。每张卡至少明确：此刻想得到什么、最怕暴露或失去什么、对在场其他人的态度与筹码、惯用说话策略、受压后的换招，以及称呼习惯、句长、直白程度和常用/避用措辞。信息不足就标为本场假设，不擅自补成长篇身世。

人物小传不是贴“冷静、善良、机敏”几个标签，也不是把背景塞进角色嘴里。它的用途是决定同一事实由不同人如何说：有人先报数字，有人先问责任，有人绕开主语，有人用命令截断。写完抽掉 `speaker` 名称复读主要台词；如果大多数句子可以互换角色而不违和，说明语言指纹没有进入正文，必须按各自目的与策略返修。方言、口头禅和语气词只能点到为止，不能代替人物差异。

#### 中文对白口播复查

对白写完后单独审一遍，不与剧情完整性审查混在一起。逐句先回答：谁在对谁说、此刻想让对方做什么或相信什么、这句话是否符合两人的身份与关系。没有当下行动，只是在替作者交代背景、解释主题或展示文采的句子，改成试探、阻止、追问、威胁、讨价、遮掩等具体说话行为，或删除。

口语化是受约束的最小改写。先冻结原句的说话人、受话人、事实命题、对象、肯否定、条件、时间、语气功能和利害关系，再调整语序、搭配与省略；这些内容任何一项发生变化，都属于剧情修订，必须单独说明，不能冒充对白润色。不得用另一句“更好听”的台词替换原句，却让人物改了立场、增加了新因果或丢掉原信息。

先静读，确认信息和指代清楚；再遮住 `delivery` 朗读，确认一口气能说完、语序像口头表达、搭配自然，代词在听觉上也能找到所指。如果一句话必须依赖括号里的 `delivery` 才像人话，就重写 `line`，不能用表演注释掩盖生硬措辞。警惕省略过度的压缩句、翻译腔的动词加代词、对称工整的格言句、报告式完整句和人物突然总结主题。例如“谁抓到他，升职也跑不了”可最小改成“谁要是抓到他，升职准没跑”；“停下。这年头唱它，会惹祸”可最小改成“别唱了。这年头唱这首歌，会惹祸”。两例都只改口头表达，不改变事实与警告对象。

口语自然不等于堆“那个、就是、然后”，也不等于套网络热词。时代、地域、职业、年龄、权力差和亲疏关系共同决定称呼、句长、礼貌与省略程度；不同人物不能共用一副作者腔。允许打断、改口、半句和留白，但关键信息不能靠含混代词丢失。最终同时保留“陌生观众看得懂”和“演员张嘴说得出”两条底线。

#### 去 AI 味与反俗套伦理七问（InkOS 戏剧脱水准则）

审视剧本中的每个段落与台词，强制过一遍 7 问：
1. 戏剧功能：本段落或台词承担什么具体剧情功能？如果删去是否影响局面推进？
2. 具象呈现：该功能是否通过可见动作、具象道具、选择代价或实际后果展现？严禁借角色之口背诵设定。
3. 情绪自证：动作是否已经在表演情绪？严禁让旁白或台词去空洞解释演员已经在流泪/握拳的情感。
4. 人物指纹：这句话换到另一个角色嘴里是否依然成立？如果成立，说明人物语言指纹丢失，必须重写。
5. 细节承载：出场细节（如 55.2 度温水、加冰块、黑猫咪咪、碎屏手机）是否真实承载关系记忆与压力？
6. 严禁狗血短剧伦理套路：改编具有科幻或严肃文学底色的作品时，严禁自行添加土味低幼的家庭矛盾（如玄关赌气吵架、淋雨买卤味、莫名其妙的病毒外置插槽）；冲突必须扎根于核心哲学命题（如算法过度顺从的虚妄 vs 真实人性的不完美与温存）。
7. 场景丰富度：严禁把全剧所有戏份图省事写在同一个房间（如 5 场戏全是 S01）；必须根据情感起伏合理安排空间转场（如从冰冷服务器机房，转入暴雨机车疾驰、天台焰火闪回与破晓晨光）。

#### 先确定戏的核心

每场先明确：谁想从谁那里得到什么、什么阻挡、采取什么办法、新信息或选择如何改变局面。
结束时至少能指出处境、关系或观众认知的变化；安静的场面也可以发生重要变化。
保持大纲中的类型、角色能力、关键结局和已确认对白。奇幻遵守自身约定，不默认改成物理写实。
检查角色何时知道什么，关键选择或反转是否有可见、可听或已建立的类型依据；不靠人物无依据地变笨推动剧情。
支撑反转的道具须有来源、持有者和必要交接，不能从“另一人拿着”直接跳到主角手里。普通取放可以合理省略，不要求拍出所有步骤。
允许悬念和类型约定留白；机制未说明时标明待确认，不擅自补出回忆、斜坡或超能力并当成原稿事实。优先用短动作或画面线索补因果，不堆解释对白。

#### 前三秒钩子必须成立

开场 0–3 秒就给一个具体的异常、冲突、危险、欲望或关系反差，让观众产生一个明确的问题。
可以是动作、静态构图中的矛盾、声音与画面的反差，不强制奔跑或连续切镜。
不能只写“悬念开场”：在交接说明中写出前三秒观众实际看到/听到什么、想追问什么。
钩子必须属于本集故事，并在后续得到发展，不能靠无关惊吓或虚假信息骗点击。
`hookBeat` 仍按原生要求指向前几拍；前三拍不等于前三秒，实际秒点由分镜复核。

#### 写进真实节拍

- 节拍是目标、办法、信息或关系的一次变化，不是一次伸手或眨眼。一个完整行动及其反应可写在同一动作条目里；不要把拿钱包、打开、取钱拆成三拍来凑结构。
- 剧本不默认给动作分配 `start/end` 时间码；估算时长仅作预算，不逐拍累加成表演排程。用“看到之后、试探、被打断、转而”等因果与先后组织行为，让人物有自己的反应速度。
- 只有明确的同步需求才保留局部时点，例如用户指定音乐踩点、对白口型或关键声音先后；不得为追求松弛删除这些要求。前三秒钩子是内容窗口，不要求每个微动作定秒。
- 台词与动作分条，`speaker/line/delivery`、人物和道具引用沿用原生格式。
- 台词从人物目标与说话习惯出发，每句话都应是试探、回避、施压、交换、遮掩或其他当下行动，并通过上面的中文口播复查。别让人物替作者解释设定或总结主题；潜台词落在选择、停顿和行为后果中。
- 动作写可见的起止状态与关键交互。复杂动作标出实现风险，由分镜拆解；不笼统宣称“必崩”。
- 反应不只是“惊恐、呆滞”。例如正在递出的东西被收回，能改变关系；不机械添加眨眼或小动作。
- 使用保守默认参数估时（语速、动作拍时只是估算）。`targetSeconds` 是写作目标，±15% 只是硬拦截带，不把接近上沿当成“正好合格”；首稿尽量落在目标 ±5%，把余量留给表演停顿。超时先删重复信息或调整段落，不优先删掉因果与表演；禁止通过提高 `charsPerSecond`、降低 `actionSeconds` 或放宽 `tolerance` 把超长正文刷成通过。
- 单句长度、场次动作、`beatsClaimed`、`cliff` 等满足现有合同；不要靠机械插动作凑格式。
- 集尾兑现本集变化并保留已确认的后续悬念，不要求每个小段都重新制造悬念。

#### 故事审查与局部返修

读完整场再检查：是否知道人物想做什么？转折有依据吗？删掉哪段仍不影响剧情？类型趣味是否保住？
问题写“节拍位置 → 观众会误解或失去兴趣的原因 → 修复目标”，不要先给整场重写结论。
无问题可以通过，不强行找缺点。审查是编辑判断；没有独立审查上下文时明确为自审。
同一阶段最多两轮定点返修，未收敛的问题标为待审，不自动无限重写。
改一拍复读相邻拍及受影响的场尾，检查人物位置、道具在哪只手、谁在场与信息状态。
区分人物/道具身份与当前状态：回忆、时间跳跃、康复、换场或换装可按剧情发生，不用“全程一致”抹掉这些变化。新增配角和关键道具要进入现有角色/资产清单。
涉及上游设定或结局变化先报告影响；不自行改其他集或更新 pins 掩盖问题。

#### 交给分镜的内容

在现有交付说明/creative-review 中按场简记：戏剧目标、类型与情绪变化、不可改的剧情事实、
前三秒钩子的可见/可听内容、关键转折、待审风险。直接写实际内容，不新增空模板或专用脚本。
注明哪些是必须保持的事实/同步要求、哪些是可由表演自然展开的过程；复用现有说明，不加 schema。分镜接收的是戏，不是需要照抄的逐动作秒表。
跨时空转场简记其叙事意图、允许变化的状态及需保留的线索；意图尚未确定就标待确认，不把观众暂时不知道等同于作者无需设计。
稿件已明确回忆或时间跳跃时，不再把该状态变化本身列为缺口；观众何时确认时空关系服从既定意图，不自动增加字幕、对白或铺垫来解释。
分镜消费这些内容和原生剧本，不能为方便生图重新发明故事。结构校验、故事审查、成片观感分别汇报。

### Step 3 — 校验 ⛔ 不能跳

```bash
node {baseDir}/scripts/cine-script.mjs validate <script.json> \
  --outline <outline.json> --art <art.json>
```

11 道质量门全是代码：时长与质量参数不得放宽默认值；每集时长在目标 ±15% 内（台词按 4.5 字/秒折算、动作按 2.5 秒/拍）、单句台词 ≤ 35 字、说话人在本场人物里或标 `VO`、每集钩子悬念落纸、**钩子具象在全集前 3 拍内兑现**（`hookBeat` 认领）、每场至少一个动作节拍、动作叙述体不混引号台词、爽点认领、角色对账、场景/光照/道具对账。`params` 仍可省略或调得更保守，但不能用更快语速、更短动作或更宽容差改变验收结论。

## 四个 skill 的接力

```
cine-outline    → outline.json （什么：结构与分集）
cine-characters → cast.json    （谁：角色资产）
cine-art        → art.json     （哪里 + 手里拿的：美术资产）
cine-script     → script.json  （戏：场次、节拍、台词）
```

seed 吃 outline.json；validate/render 的 `--outline` `--art` 负责对账和显示名字。四份 JSON 各自的报告都带导出按钮，改完都能喂回各自的 render/validate。往下一层是分镜：镜号、单镜头时长、首帧提示词、生成批次单都在那边。

## 边界

- 报告界面内置中英（`--lang`，默认中文、或跟 script.json 的 `lang` 字段）；台词语言跟剧走
- 时长是**估算不是秒表**——默认值按自然对白保守预算；`params` 只允许收紧估算和质量门，不能由创作模型放宽来消除超时
- `VO` 是画外音统一记号，谁的心声写在 `delivery` 里；台词本里 VO 单独成组
- 不设每集场次上限——换景次数只进 KPI 统计不设门，生成与一致性维护仍有成本
