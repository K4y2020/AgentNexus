# AgentNexus UI Style Guide

## Source of truth

The UI uses the existing **shadcn/ui radix-nova + Radix + Tailwind CSS v4 +
Lucide** stack configured in `components.json`. Do not add another UI framework
or hand-build a competing set of controls. Rakazo informs product structure;
AgentNexus components and theme tokens own the implementation.

The default AgentNexus palette follows Rakazo's neutral, flat surfaces in both
color modes. Other saved palettes remain selectable. Bot navigation uses
`Button size="list"` with `Avatar` and two text tiers; Topic branches remain
separate from the primary chat. The chat and landing composers share
`CHAT_COMPOSER_SURFACE` in `src/pages/chatLayout.ts`.

| Concern                                      | Canonical source                                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Controls and their variants                  | `src/components/ui/`                                                                       |
| Color palettes and user customization        | `src/lib/themePalette.ts`                                                                  |
| Generated palette CSS                        | `src/themePalettes.generated.css`, generated by `node scripts/generate-theme-palettes.mjs` |
| Semantic tokens, typography, shared geometry | `src/index.css`                                                                            |
| User font preferences                        | `src/lib/uiFontPreferences.ts`                                                             |
| Visual reference                             | Storybook: `Foundations/Primitives`                                                        |

Never edit generated palette CSS directly. Reuse existing tokens before adding
new ones. A new theme token needs light and dark definitions at its owning source.

## Color and typography

| Purpose                        | Use                                                      |
| ------------------------------ | -------------------------------------------------------- |
| Page                           | `bg-background text-foreground`                          |
| Framed content                 | `Card`                                                   |
| Overlay                        | `Dialog`, `Popover`, `DropdownMenu`                      |
| Supporting text                | `text-muted-foreground`                                  |
| Separators                     | `border-border`, `border-border-weak`                    |
| Selected navigation            | Existing sidebar selection helpers/tokens                |
| Working / dispatched           | `Badge variant="info"` plus a label/icon                 |
| Waiting for input              | `Badge variant="warning"`                                |
| Successful / ready             | `Badge variant="success"`                                |
| Failed                         | `Badge variant="destructive"`                            |
| Unknown / offline              | `Badge variant="secondary"`, with the actual state label |
| Body and controls              | `text-ui`                                                |
| Supporting labels and metadata | `text-sm`                                                |
| Section title                  | `text-base font-semibold`                                |
| Page/dialog title              | `text-lg font-semibold` or the component default         |
| IDs, paths, code               | `font-mono`; retain the appropriate text tier            |

`text-ui` and `text-sm` follow Appearance font settings. `text-xs` is a legacy
alias of `text-sm`, not a third tier. Do not use `text-[11px]`, viewport-scaled
type, or negative tracking. Semantic status badges keep their label in readable
foreground text; colored icons and tinted surfaces provide the status cue.

## Components, sizes, and layout

- Actions: `Button`; use `variant` for intent and `size` for density. Heights
  are `xs=24`, `sm=28`, `default=32`, `lg=36` CSS pixels. Default icon buttons
  use 32px on desktop and 40px on mobile. Do not override with page-local `h-*`
  or `size-*` just to make one button look different.
- Icon-only actions: Lucide icon inside `Button`, with `aria-label` and
  `Tooltip`. Ordinary command buttons may combine an icon and text.
- Forms: `Input`, `Textarea`, `Select`, `Switch`; pair each control with a
  visible label and accessible association. Use native numeric inputs where
  appropriate. Keep focus, disabled, invalid, and loading states intact.
- Views: `Tabs variant="line"` through `TabsList` for view navigation;
  the default tab-list variant for segmented choices. Use `Collapsible` for
  expandable records. Preserve keyboard and ARIA behavior from Radix.
- Avatars, labels, loading: `Avatar`, `Badge`, `Spinner`. Status data is owned
  by the application, not inferred by the visual component.
- Layout may use Tailwind flex/grid, `gap-*`, `p-*`, `min-w-0`, `flex-wrap`,
  and responsive utilities. Prefer the existing spacing scale: 4/8/12/16/24px.
- Use existing radius tokens: `rounded-sm` (4px), `rounded-md` (6px),
  `rounded-lg` (8px). Existing shadcn defaults for avatars, badges, dialogs,
  and cards remain authoritative; do not restyle those per page.
- Page sections are unframed. Cards are for individual repeated items or
  genuinely framed tools. Do not put a second decorative card inside one.
- Use `className` at call sites for placement and responsive layout. Repeated
  visual differences belong in the shared component's CVA variants. Inline
  styles are only for runtime geometry, user values, or renderer integration.

```tsx
<Badge variant="info">
  <Spinner aria-label="Working" />
  Working
</Badge>
<Button variant="outline" size="sm" loading={saving}>
  <SaveIcon />
  Save
</Button>
```

## Adoption and verification

The shared controls and theme system already exist. This iteration adds status
badge variants and adopts them in `A2ACollaborationCard`; it does not claim that
every legacy Bot/settings/sidebar view has been migrated.

Run `npm run storybook -- --host 127.0.0.1` from `web`, then open
`Foundations/Primitives`. The gallery shows light and dark token references,
control variants, and interaction states. Check narrow widths, long labels,
keyboard focus, and Appearance font settings before adopting a new pattern.

Run `npm run type-check`, relevant `npm test -- <files>`, and `npm run build`
after changing shared controls. Shared UI sources are currently excluded by
the repository's oxlint configuration; this document is a review convention,
not an automated ban on all legacy styling.
