# Cine 因果与连续性规则优化

后续发布状态：共享 Cine 已发布至 v25，见 [发布与真实 Topic 验证](CINE_SKILL_RELEASE_20260910.md)。下文保留本轮优化时的观察与限制。

归因更正：混合提示词审查不能证明剧本链路被反向模板污染，详见 [分层与测试归因更正](CINE_LAYER_ATTRIBUTION_AUDIT.md)。

## 实现范围

修改 `novel-script`、`novel-storyboard` 及 `config.yaml` 的预载核心，没有新增 schema、状态机、生成接口或逐动作时间字段。

- 关键选择和反转需要可见、可听或已建立的类型依据；缺失机制不当作既成事实。
- 支撑剧情的道具检查来源、持有者、必要交接；普通动作允许省略，不强制拍全流程。
- 身份与状态分开：回忆、换场、康复或换装不是自动的连续性错误。
- 匹配剪辑只锁定承担连接作用的机位、构图和物件位置，不冻结整片环境或表演。
- 逐镜检查行动、对白、距离和反应负载，不以镜头数或时间码数量证明可执行。
- 审查区分确定断裂、合理省略、待确认意图、生成风险；优先调整限制的作用范围，不默认删掉计划配角或给明确回忆补解释。

## 验证与限制

入口/预载回归测试 39 项通过，相关补丁 `git diff --check` 通过。新增两份文字评测提纲：滑板车喜剧的道具与角色范围冲突，以及回忆转场中的身份、健康状态和动作负载。

进行了两次独立首次输出检查，中间只收紧 skill 规则，没有把前次答案或逐项纠正发给第二次模型。两次均为 `gpt-5.6-luna` 路由记录，实际服务器 bundle 哈希已核验，工具调用为零，未生成任何媒体。网关未提供上游模型身份，不能声称上游独立验证。这是作者自审的文本冒烟测试，不是独立盲审或广泛稳定性评测。

两次输出都识别了滑板车返回依据不足、杂货袋归属、头盔交接、玩具回到女子手中的缺口及三秒动作过载；均认可过去健康/现在受伤可以属于合法状态变化。

历史输出中确有删除邻居、为回忆补提示的建议。但邻居用例混入了未标明作用层的生成限制，不能据此评价纯剧本生成，也不能证明系统模板注入故障；这项跨层评分撤回。回忆的轻提示建议属于编辑判断，不直接等同于技术缺陷。规则存在和字段检查通过均不能证明稳定创作质量。

原始证据位于 `outputs/cine-continuity-eval/` 与其 `refined/` 子目录：请求、完整回答、服务器快照、模型事实及实际 bundle 均保留。
