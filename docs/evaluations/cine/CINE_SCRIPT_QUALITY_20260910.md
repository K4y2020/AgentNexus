# Cine 纯剧本创作质量检查

## 范围与方法

本轮仅检查剧本是否可进入分镜，不检查 H3 格式、生成负面约束或成片电影感。使用共享 Cine v25 和两个新 Topic；模型事实解析为 `gpt-5.6-luna`，网关未公开上游身份。

两个创作需求和私有评审检查点先写入 `tests/fixtures/cine_creative_eval.json` 的 script_creation 用例。作者只收到创作需求，没有收到评分清单、其他答案或范文。首次输出各审查一次，之后最多两轮带具体问题的返修。返修结果明确标为经过反馈指导，不冒充独立首稿能力或新的 skill 版本效果。

通过标准是编辑判断：开场有具体吸引点，人物动机可读，转折不依赖关键事实矛盾，结尾回应已建立冲突，动作与对白预算合理。普通取放细节可以交给分镜处理，不把所有省略都升级为剧本错误。没有做独立盲审或真实观众评测。

## 结果

喜剧最终稿已删掉求婚线，不把中间稿问题算在最终稿上。最终稿 115 个非空白台词字符，按当前默认 4.5 字/秒约 25.6 秒；这只是对白估算，不含需要额外时间的动作和停顿，也不代表实测一定超时。它是负载风险与编辑取舍依据，不是新的硬性生成门。

悬疑最终稿《不去十二层》为 79 个非空白台词字符，同口径约 17.6 秒。录音引出偷配钥匙，女方明确不让其进入家中，改变电梯去向作为行动落点。手机最终取得方式、开关门和按楼层的具体动作应在分镜明确；不要求剧本逐手势排秒。

两份首稿均未在本次编辑审查中通过，因此不能宣称 Cine 已能稳定自主产出合格剧本。悬疑稿通过的是本稿的文字阶段，并且是在两轮反馈后。喜剧达到返修上限，停止自动重写，不因已投入时间强行通过。
