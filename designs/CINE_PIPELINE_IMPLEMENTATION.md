# Cine 通用拉片流水线实现方案

> 状态：待实施方案 v1，不是完成报告。
> 编写日期：2026-09-05。
> 范围：AgentNexus 内的通用拉片 Bot；不绑定任何影片、素材目录或改编世界观。
> 当前入口：`examples/cine/config.yaml`。

## 1. 产品目标

用户提供视频或选择已有项目，Cine 能按明确范围完成：

```text
素材接入 -> 元数据与时间轴 -> 候选切镜 -> 帧/片段/音频证据
         -> 单镜头核验 -> 相邻镜头剪辑分析 -> 复核清单 -> HTML 报告
                                                        |
                                            用户选择启用改编
                                                        v
                         改编分镜 -> AI素材任务 -> 剪辑执行计划
```

首要产品是“有证据、可复核的原片拉片”，不是自动复述剧情，也不是生成视频平台。
电影、短片、广告、动画、实拍共用流程；分析策略可以不同，但不能复制特定影片的时间码和结论。
自动切镜、模型解读、人工核验分别记录；不能因为页面生成成功就宣告全片分析完成。

## 2. 当前基线

| 能力 | 当前状态 | 实际边界 |
|---|---|---|
| Cine Bot 定义 | 已有 | 通用身份与流程提示词，使用现有 claude-sdk Harness |
| 独立 Bot Home、主聊天 | 本机已注册 | 不意味着其他安装自动拥有 Cine，部署仍需补齐 |
| film-analysis 技能 | 已有 | 方法说明与初始化脚本，不是完整执行器 |
| media_project.py | 已有 | ffprobe 读取元数据、拒绝覆盖、创建四个空 JSON 台账 |
| 基础测试 | 已有 | 配置加载、防覆盖、原文件不变；不覆盖完整拉片质量 |
| 统一提问 | 平台已有实现 | 复用 sys_ask_user；待回答信息目前不能承诺跨服务重启持久恢复 |
| 镜头检测、转写、报告生成 | 尚未通用化 | 历史项目脚本存在影片专属路径和假设，不能直接算已实现 |
| 动态视频核验、剪辑关系分析 | 未实现通用闭环 | 不得以三张截图替代整段动态审看 |
| 断点续跑与验收门禁 | 未实现 | 需要本方案的项目状态与证据检查 |

已有历史影片可作为回归参考，但不得成为默认输入、唯一验收样本或通用工具的依赖。
当前脚本的 `size_bytes + mtime_ns` 仅为快速变化检测，不是可靠内容标识。

## 3. 用户流程与范围

### 3.1 新任务

1. 主聊天接收路径、附件或已选项目；没有素材时询问，不扫描无关目录。
2. 有多个视频时通过统一提问卡片选择，不能直接取目录中的第一个文件。
3. 明确分析范围：指定片段、全片索引、逐镜精校；这三种交付不能混称。
4. 先读取元数据、估算磁盘和调用成本，用户确认后执行昂贵阶段。
5. 每部影片建立独立项目，Topic 记录稳定 `cine_project_id`；它不是 Git Project ID。
6. 先跑一个约 60–120 秒的代表片段，确认方法，再推进全片。

### 3.2 继续任务

同一影片的补证据、纠错和复审继续原项目，不新建数据副本。
主聊天用于入口和项目选择；具体工作使用关联 Topic。已有 Topic 不应被偷偷改绑其他影片。
如果同一素材需要另一种改编，新增计划版本，不覆盖原片台账。

### 3.3 输出

- 默认：原片镜头表、剪辑关系、证据媒体、待核验清单、HTML。
- 可选：改编分镜、角色/场景资产需求、AI 素材任务、剪辑执行表。
- 不默认执行：全片云端上传、付费视频理解、素材生成、成片发布、版权授权操作。

## 4. 实现边界

继续使用 `Bot -> Session -> Runner -> Harness`，不新增 Harness、虚拟电脑或独立调度服务。

- Bot：解释需求、选择流程、组织解读、提问和汇报。
- Python 工具：元数据、时间轴、媒体处理、数据验证、确定性报告生成。
- 多模态模型：解释实际送入的证据，输出受校验的结构化结果。
- 项目执行器：阶段状态、输入版本、重试、暂停恢复、验收结算。
- 用户：范围确认、歧义复核、费用和敏感操作批准。

第一版以单项目单写者运行，不默认派出多个子 Agent。
剪辑分析需多镜头上下文，不能简单把每张截图分发给互不知情的 Agent。
A2A 和独立审查是后续增强，不是最小流水线运行的前置条件。

## 5. 项目存储与数据契约

建议在 `examples/cine/skills/film-analysis/` 下增加 `pipeline/` Python 包，
将现有 `media_project.py` 保留为兼容入口。下列模块与字段均为目标设计，尚未全部存在。

```text
<bot-home>/scratch/projects/<project-id>/
  project.json                 # 模式、授权源、范围、当前版本、关联 Topic
  source.json                  # 原始 ffprobe 与内容标识
  runs/<run-id>/run.json        # 执行参数、状态、阶段产物和验收
  revisions/<revision-id>/
    timeline.jsonl             # 源流 PTS 索引，按需生成
    cut_candidates.json
    source_shots.json
    transcript.json
    editing_relations.json
    adaptation_shots.json      # 可选，严禁覆盖 source_shots
    generation_jobs.json       # 可选
    edit_plan.json             # 可选
    evidence/                  # 帧、边界片段、音频证据
    report/                    # HTML 与可播放预览
    validation.json
```

### 5.1 通用规则

所有记录含 `schema_version`、稳定 ID、`source_id`、`revision_id`。
源路径作为本机定位信息保存；HTML 默认显示文件名和相对证据路径，不泄露用户目录。
新项目生成随机稳定 ID；展示名称改变不能改变 ID。

| 表 | 最小字段 |
|---|---|
| 项目 | project_id、source_id、scope、mode、current_revision、topic_id |
| 源媒体 | source_id、sha256、size、mtime_ns、streams、time_base、duration、probe |
| 候选切点 | candidate_id、stream_id、pts、detector、parameters、score、status |
| 原片镜头 | shot_id、source interval、candidate_ids、observations、evidence_ids、verification |
| 转写 | segment_id、audio stream、source interval、text、language、method、verification |
| 剪辑关系 | relation_id、shot_ids、relation_type、claim、evidence_ids、verification |
| 改编分镜 | adapted_shot_id、source_shot_ids、original_content、target_duration、version |
| 生成任务 | job_id、adapted_shot_ids、asset_refs、planned_duration、constraints、status |
| 剪辑执行 | edit_id、adapted_shot_id、job_ids、target_duration、selected_asset、actual_in/out |

模型只提交解读字段，不能覆盖工具产生的源时间轴、源文件标识和执行状态。
导入已有项目时保存来源和原状态；不把历史结论升级为当前核验结果。

### 5.2 时间规则

- 原始流的整数 PTS 与有理数 time_base 是权威；秒数、HH:MM:SS.mmm 是显示投影。
- 保留非零 start_time；代理视频从零开始时必须保存映射，不能混用源时间与播放时间。
- 区间采用左闭右开；最后一帧的显示时长依据解码时间轴处理。
- CFR 可记录帧号辅助定位；VFR 不得使用平均帧率反推精确切点。
- 音轨保留自身时间基和相对偏移，检测音画同步问题而非强行对齐。
- 生成时长、成片目标时长、实际素材取用区间严格分离；无实际素材时后者为 null。

### 5.3 证据与核验

每个事实保留证据 ID；证据记录文件相对路径、哈希、源区间、提取命令与工具版本。
核验按维度记录 `boundary / visual / motion / dialogue / sound / editing`，
各维度可为 `unreviewed / model_reviewed / human_reviewed / disputed / unavailable`。
不适用的维度必须有原因，不能简单填 PASS。模型自报置信度不是人工确认。

抽帧只能支持可见画面事实；“声音提前进入”“镜内转身”“人物消失”等需要对应片段或音轨。
视听解释与可见事实分字段，不把解释写成源素材事实。

## 6. 模块与阶段职责

| 建议模块 | 输入 -> 输出 | 实现要求 |
|---|---|---|
| project.py / schemas.py | 请求 -> 项目与合法台账 | 复用 Pydantic；参数和外部结果都校验 |
| probe.py | 视频 -> 元数据、时间轴、标识 | FFprobe/FFmpeg；内容哈希可缓存但变化时失效 |
| detect.py | 授权区间 -> 候选切点 | 首版选 PySceneDetect；记录配置，保留渐变与误切候选 |
| evidence.py | 候选区间 -> 帧、短片段、音轨 | 前中后帧仅作索引；边界附近保留动态证据 |
| transcribe.py | 指定音轨 -> 自动转写 | 复用可用 Whisper；无依赖时显式 unavailable |
| analyze.py | 证据包 -> 结构化镜头解读 | 能力探测；只有图片输入时不得声称已审看视频 |
| relations.py | 相邻镜头组 -> 剪辑关系 | 以序列批次处理；跨批次保留重叠上下文 |
| validate.py | 台账、证据 -> 问题清单、验收 | 无效引用、时间越界、未核验覆盖不能通过 |
| render.py | 已校验台账 -> HTML | 固定模板、转义文本；不让模型每次重写页面 |
| adapt.py | 已选源版本 -> 制作计划 | 按需启用；同镜头与素材可多对多关联 |
| runner.py | 项目、阶段 -> 可恢复运行记录 | 单写者、原子提交、缓存和有界重试 |

工具依赖先检测再使用。缺少 FFmpeg、转写模型、视频输入能力或网关额度时，
应返回具体能力缺口和可继续的阶段，而不是让模型编造替代结果。
原生 CLI、SDK 和模型 ID 不决定真实多模态能力，应在选定 Host/网关上做小样探测。

## 7. 执行、续接与错误恢复

### 7.1 状态模型

执行状态：`queued / running / waiting_input / interrupted / failed / finished`。
验收状态：`unverified / partial / accepted / rejected`，与执行状态分开。

`finished` 只表示本轮没有剩余执行步骤；“完整拉片交付”还需范围覆盖和证据检查通过。
一期工具可返回 `index_ready`，不得因此产生 `accepted_full_analysis`。

### 7.2 写入与恢复

- 首版使用经验证的跨平台文件锁库，保证同一项目只有一个执行器写入。
- 临时文件与最终文件位于同一文件系统，完成校验后原子替换；最后提交阶段清单。
- 发布报告引用不可变 revision；失败不能破坏上一版可用报告。
- 每个阶段缓存键包含源内容哈希、范围、输入版本、参数、工具版本和实际模型配置。
- 源素材改变后下游失效；只改变报告模板无需重新转写或重新解码全片。
- 进程崩溃后不把残留 running 当成功；核对阶段清单和产物后从最近已提交步骤续跑。
- 有外部调用但收据不明时标记结果未知，不无条件重试产生重复费用。
- 清理只操作项目内已登记的派生产物，禁止删除原片或任意模型返回的路径。

### 7.3 任务续接

项目任务关联 `role + child_session_id + input_revision`，而不是用标题判定续接。
执行者补路径、修正分析、处理审查意见时继续原子会话；复审继续原审查会话。
独立任务才建立新关联，理由文本不能替代关联检查。
这些规则应由项目执行器校验；平台现有 new_task_reason 放行不足以作为最终保障。

## 8. 提问、预算与 A2A

问题来源包括素材选择、范围选择、边界争议、音轨选择、外部上传和改编方向。
普通问题用 sys_ask_user；不通过解析 Markdown 生成按钮。
等待回答前先保存项目阶段状态；答案绑定 project_id、run_id、question_id 和输入版本。
过期答案或已经更换素材的答案不能应用到新版本。
当前平台提问注册表为内存状态，Cine 必须保存待解决问题描述；重启后重新确认，不能伪造已回答。

云上传、付费调用、磁盘占用和最长执行时间有显式预算；预估与实际用量分别记录。
设置模型由用户配置决定，不能由编排器悄悄换成另一模型继续。

A2A 派发带原始请求 ID、项目 ID、输入版本、授权证据路径和预期产物。
对方只能提交结果建议，不直接成为项目台账写入者。主执行器校验后合并。
附件路径不等于附件已传递；跨 Host 需确认接收方拥有可读副本及相同内容标识。
一期不要求自动跨 Bot 互审；先保证单 Bot 可重复运行。

## 9. HTML 与交互

保持 AgentNexus 现有组件和样式规范，不新建一套聊天或提问 UI。
Bot 聊天展示阶段、进度、阻塞和报告入口；详细拉片放在报告中。

报告包括：

- 素材与范围摘要；候选数、已核验数、未核验数分开显示。
- 镜头列表、前中后证据图、按源时间定位的片段回放。
- 原片观察、模型解读、人工纠正分栏或标签区分。
- 相邻镜头剪辑关系、对白与声音证据。
- 待复核筛选、错误信息、可定位的证据链接。
- 仅在启用后显示改编和 AI 制作视图。

源视频浏览器不支持时生成兼容预览副本，不覆盖源文件。
首版支持本机静态 HTML 加相对媒体文件；交互必须在允许的浏览器环境验证。
媒体加载失败要有可见状态，不能显示空白播放器却宣告验证完成。

## 10. 实施顺序与退出标准

阶段编号 C0–C4 独立于平台 Bot/A2A 的 Phase 编号。

### C0：通用项目与契约

- 增加项目 schema、素材选择、稳定 ID、版本与锁。
- 保留现有初始化命令；新增显式 resume，不能取消“已有目录拒绝覆盖”的保护。
- 改造初始化的部分写入失败处理；异常产物不成为可恢复的完成阶段。
- 提供可重复安装/更新 Cine bundle 的命令，不能靠手工写数据库作为长期部署方式。

退出：两部不同影片建立不同项目；无输入会询问；重名不覆盖；源变化可检测；
Windows 中文/空格路径可用；并发两次启动只有一个取得写锁。

### C1：确定性媒体索引与报告

- 实现候选检测、证据提取、元数据时间轴、候选索引 HTML。
- 不依赖多模态模型就能生成可审阅底稿。
- 首期不要求自动转写或自动改编；缺失项明确显示。

退出：选定 60–120 秒片段的所有候选区间覆盖请求范围，无非法重叠、空区间和越界证据；
硬切、闪光和连续动作均可逐一查看；所有切点仍标为候选；HTML 媒体正常加载。

### C2：视听解读与剪辑关系

- 接入一种经过小样验证的多模态模型和一种可选本地 ASR。
- 单镜头与相邻镜头批次分别分析，输出需通过 schema 和引用验证。
- 建立复核清单，允许纠正边界并使相关分析失效。

退出：以人工标注的小样核对至少 20 条镜头记录和 5 类剪辑/声音关系；
每条已确认事实都有适当证据，未确认的不能混入已确认统计；
报告记录检测 precision/recall 与边界容差，不用模型置信度冒充准确率。

### C3：全片、恢复与协同验收

- 分批处理长片，检查跨批边界，实施预算、取消和断点续跑。
- 为执行、补正、复审保留稳定任务关联；接入必要的 A2A。
- 完成项目层 required-task 验收，禁止未完成补正被旧 PASS 覆盖。

退出：执行中终止进程后可以恢复已提交阶段；模型 429、无额度、坏 JSON、磁盘不足
均产生可解释状态；重复回调不重复合并；两部影片并行不串证据；
“子任务未能修改，主任务宣告成功”回归场景必须被项目验收拒绝。

### C4：可选改编与 AI 制作计划

- 增加改编表、资产依赖、生成任务和剪辑执行表。
- 先交付计划，不默认调用图片/视频生成平台。

退出：短插镜可以映射较长素材；一个素材可供多镜头使用；声音可跨镜；
未生成素材的 actual_in/out 为 null；改编内容与源片观察始终可区分。

## 11. 测试与验收样本

确定性测试使用自制短视频，不依赖任何单部商业影片：

1. CFR 硬切、连续运动、单帧闪光、黑场和渐变。
2. VFR、非零起始 PTS、多音轨、无音轨和损坏文件。
3. 路径包含中文、空格及 shell 特殊字符；命令使用参数数组而非拼接 shell。
4. 进程中断、写入中断、重复启动、恢复时源文件变化。
5. 返回空分析、坏 JSON、无效 shot_id、越界时间和缺证据的模型结果。
6. 无真实素材却声称选好了生成片段、只看截图却声称验证了声音。
7. 同一任务反复补充信息不创建替代会话；明确独立任务可新建。
8. 两部不同类型的授权影片小样实测，人工抽查，再进入全片试运行。

全片实测要报告计算时间、峰值磁盘、模型请求数、实际费用和人工复核量。
没有实际调用的外部模型、没有打开验证的浏览器、没有动态审看的片段，都应明确记为未验证。

## 12. 下一迭代清单

只做 C0 + C1 的短片闭环：

1. schemas.py：项目、源时间轴、候选镜头、证据与阶段状态。
2. project.py：新建、锁、原子写入、版本与 resume。
3. probe.py / detect.py / evidence.py：选定区间检测与证据提取。
4. validate.py：时间、引用、媒体存在性和阶段完成检查。
5. render.py：固定模板的候选镜头索引，不生成未经核验的镜头解读。
6. runner.py：显式阶段命令、失败状态、断点复用。
7. Cine 技能改用上述命令，不再现场拼接影片专属脚本。
8. 自制媒体回归 + 两种不同素材的小样验收 + 浏览器检查。

交付措辞必须是“通用候选索引流水线可用”，而不是“全自动完整拉片已完成”。
本轮不做 Docker、桌面接管、云上传默认开启、全片自动改编或新的多 Agent 平台。
